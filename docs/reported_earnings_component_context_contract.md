# Reported earnings component context

`reported_earnings_component_context/v1` extends the existing reviewed interim overlay
and explicit-session projection. It admits only the reported income-statement line 21
investment-property disposal result when the literal row label contains both disposal
and investment-property identity. Exact geometry, unit, consolidated scope, assurance,
period, citation and knowledge-time gates remain required. No OCR letter or digit repair.

An already qualified physical label is preserved. For incomplete label identity only,
TSV label ownership runs from the exact code's source hierarchy line up to, excluding,
the next visible code-column line in the same block and paragraph. Only label selection
uses this window; amount cells keep physical midpoint bounds, including malformed neighbours.
Both-sided labels and ambiguous ownership fail closed. Literal token orders and label bounds
are retained in citation lineage. No ticker-specific extraction rules.

The component is context only, excluded from legacy citations and valuation input use.
A qualified, current, nonzero result sets `NON_RECURRING_COMPONENT_PRESENT_OR_POSSIBLE`.
Recurrence stays `UNKNOWN`: a reported disposal result does not establish a one-off adjustment.
No normalized EPS, annualization, TTM, score, threshold or recommendation follows.
Missing, zero, stale, conflicted, unqualified or post-cutoff evidence leaves quality `UNKNOWN`;
absence never proves clean earnings. Existing packet and AI consumers preserve this context.
